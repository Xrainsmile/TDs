# 试玩记录器使用说明

试玩记录器用于自动收集客观操作数据，人工只补充无法从程序判断的压力、选择原因、爽点和局末体验评分。

## 自动记录内容

- 每波时长、敌人最远路径进度、击杀、漏怪、基地生命和金币变化。
- 波末塔类型、数量与星级。
- 每次抽牌的5张候选、花费、使用牌、目标和选择耗时。
- 波后三选一候选、角色桶、最终选择、决策耗时和估算纠结度。
- 放置、移动、交换、合并、升级和拆除塔等关键操作。
- 四套已实现流派的方向出现、基础成立和质变时间点。
- BOSS 出现、击败或逃脱，以及 BOSS 战斗时长。
- 各塔的攻击次数、有效伤害、伤害结算次数、击杀数和 BOSS 伤害。
- 直接弹道、弹射、分裂、毒伤、毒爆、供电戳击、过载第二戳、控制爆破、穿透和剪线等机制贡献。
- 每波有效伤害及前三名伤害来源，用于定位获得哪张牌后发生了强度跃迁。
- BOSS 伤害来源占比，以及 BOSS 剩余 75%、50%、25% 生命时的战斗时间。
- 本局敌群变体（标准纵队或成组来袭）。
- 胜利、失败和中途重开。

伤害只统计敌人实际损失的生命值，溢出伤害不计入。例如对剩余 5 点生命的敌人造成 100 点伤害，本次有效伤害记为 5。持续伤害按累计生效“目标秒”统计，不再把每个渲染帧算作一次命中；底层仍只保存聚合结果，因此 Web 与小游戏端使用同一份轻量数据结构。

估算纠结度规则：

| 决策时间 | 估算纠结度 |
| --- | --- |
| 小于2秒 | 0 |
| 2至5秒 | 1 |
| 5至10秒 | 2 |
| 10秒以上 | 3 |

该分数只用于初筛。走神、阅读和误触需要在导出的 Markdown 中人工修正。

## 导出方式

一局结束后，胜利或失败弹窗会显示“导出记录”。

- Web：下载一份 Markdown 报告和一份 JSON 原始事件记录。
- 微信小游戏：Markdown 复制到剪贴板；Markdown 和 JSON 同时保存到小游戏本地存储。
- 每个平台最多保留最近20局，存储键为 `td.playtest.sessions.v1`。

Web 调试时还可以在页面控制台使用：

```js
__TD_PLAYTEST__.latest()       // 最近一局或当前草稿
__TD_PLAYTEST__.list()         // 最近20局
__TD_PLAYTEST__.exportLatest() // 导出最近完成的一局
```

## 人工补充内容

导出的 Markdown 已预留以下字段：

- 每波主观压力、期待和感受。
- 三选一纠结度修正与选择理由。
- 获取爽、成型爽、战斗爽或逆转爽事件。
- 选择意义、构筑身份、成长期待、风险回报、失败归因和再开意愿。
- 下一局想改变的策略。

完整评分口径见 `doc/playtest-record-template.md`。

## 模块边界

- `PlaytestRecorder.ts`：纯 TypeScript 数据层，不依赖 Cocos 节点。
- `PlaytestStorage.ts`：平台检测、持久化和导出。
- `SceneInitializer.ts`：只负责在游戏入口调用记录 API，并构造可序列化快照。

记录失败只输出警告并回退内存，不应阻断战斗流程。
