# 美术资源规划：引入时机 / 生产方案 / 动画方案

本文档是美术相关的总纲决策记录，回答三个问题：**什么时候引入美术、图从哪来、动画怎么解决**。

> **核心结论**：本项目的美术衔接架构已提前做好（`VisualFactory` + `VISUAL_SKINS`），"什么时候引入"的决策权在玩法节奏而非技术阻碍。总方针是——**管线验证要早，批量生产要晚**。

---

## 一、架构现状：为什么随时可换

视觉层预留了干净的切换点（见 `assets/scripts/core/visuals/`）：

- `VisualSkins.ts` 的 `VisualKind = 'graphics' | 'sprite' | 'spine' | 'particle' | 'prefab'`——每个视觉条目自带 `kind` 字段；
- 换美术 = 改 `VISUAL_SKINS` 注册表条目 + `VisualFactory` 里按 `skin.kind` 分支加载资源，**返回节点类型不变、transform 驱动不变**；
- 战斗逻辑、executor、命中时序代码零改动。

**美术需求的天然清单**：`VISUAL_SKINS` 注册表里每个 `visualEffectId` 就是一条美术需求。美术生产的终点动作 = 把该条目 `kind` 从 `graphics` 改成 `sprite` 并填上 asset 路径。

动画架构同样是"程序动画优先"：`VisualFactory` 只负责"节点长什么样"，攻击动画（吸管戳击 scale 伸缩、打蛋器 rotation、缝衣针 position 位移）由 executor 每帧驱动 transform——**换皮不换动画逻辑**。

## 二、引入时机：四阶段节奏

批量做美术的最大风险不是技术，是**返工**——美术绑定具体的 `visualEffectId`、攻击方式、塔/敌人种类，而卡牌/词条系统仍在演化，玩法每调一次都可能废掉一批资源。

| 阶段 | 触发信号 | 做什么 | 成本/风险 |
|---|---|---|---|
| **0. 现在** | — | 继续 Graphics 占位（地图/UI/单位全部不动）；只做**主题设定**（文字决策，零生产） | 零成本 |
| **1. 管线验证** | 卡牌系统编译通过后（近期） | 挑 1 塔 + 1 敌 + 1 特效做真资源，走通 `VisualFactory` 的 `sprite`/`particle` 分支，验证加载/锚点/scale/资源路径 | 极小，趟平所有管线坑 |
| **2. UI 先行** | 给朋友试玩前 | 卡牌框、按钮、HUD 等静态图。不受玩法数值变动影响，返工风险最低，对"像个游戏"提升最大 | 低 |
| **3. 批量替换** | **玩法冻结**后：塔/敌人表不再增删、流派构筑验证完、准备对外测试或提审 | 全部塔/敌人/子弹/fx 换真资源 | 高，但此时不返工 |
| **4. 平台适配** | 上微信真机前 | 主包 4MB 限制、分包加载、图集压缩 | 美术量定了才好做 |

两个补充原则：

- **阶段 1 与阶段 3 必须分开**。管线验证只要 1~2 张图，暴露所有真问题（锚点/尺寸变化、spine 兼容性、resources 还是 bundle），但不绑死任何玩法。
- **提前引入的反向信号**：当 Graphics 占位已无法传达玩法信息时（如"毒箭流"和"燃烧流"的箭塔画面上读不出差异，玩家无法感知自己的 Build），美术就从装饰变成了**玩法可读性**的一部分，属于功能缺陷，应提前引入。

### 阶段 1 的最佳候选：爽点瞬间

管线验证对象不选"最丑的"，选**爽感放大器**。当前两个已成形流派的爽点峰值瞬间在 Graphics 下传达不出来：

- **毒爆连锁**（橡皮筋弹射→全屏上毒→毒死爆炸→连锁）：瘟疫清屏的爽感 80% 在视觉，现在只是几个橙色圆环依次出现；
- **供电攻速流**（充电宝锁定攻击最高的吸管，攻速+35%+暴击）：攻速拉满后 thrust 矩形伸缩糊成一团，"神级吸管"威风打折。

阶段 1 顺手做掉三件程序反馈（一天工作量，质变"像个游戏"）：塔待机呼吸 Tween、受击闪白、hit-stop（命中 1~2 帧停顿）。

## 三、主题决策

- **主题换皮成本极低**（吸管 ↔ 长枪 ↔ 植物 ↔ 科幻），不是关键决策，可以留到玩法冻结后再拍；甚至可同一套机制做两版皮，用真实点击数据选题材。
- 当前代码里已萌芽"厨房/生活物品"方向：`bubble_tea_straw`（奶茶吸管）、`whisk`（打蛋器）、`spatula`（锅铲）、`needle`（缝衣针）。继续沿用，除非有强理由推翻。
- 主题决定的是**吸量**（图标+前 3 秒画面），后置；**留存**由核心循环决定，是当前主战场。

## 四、生产方案：图从哪来

| 方案 | 成本 | 速度 | 风格统一性 | 定位 |
|---|---|---|---|---|
| **AI 生成** | 每张几毛~几元 | 极快，一天出全套 | ⚠️ 靠固定 prompt 模板/种子控制 | **主力来源** |
| **素材库**（Kenney/itch.io/爱给网） | 0~几百元 | 即时 | ✅ 成套天然统一 | 补 UI、图标 |
| **约稿**（米画师等） | Q版单体 100~500 元 | 慢（按周排期） | ✅ 依赖单画师 | 只给游戏图标/主视觉（唯一影响吸量的单点） |

**推荐混合方案**：AI 批量生成塔/敌人/特效底图 → 人工筛选 + 统一后处理 → UI 图标用素材库 → 游戏图标预算内约一张最好的。

### 风格选型：推荐 Q 版简笔

生产前唯一要拍板的决策。候选三选：

1. **Q 版简笔/扁平矢量（推荐）**：粗圆深色描边 + 平涂大色块 + 最多一层二分阴影 + 高饱和糖果色 + 圆润夸张比例，**完全不刻画材质**（不画金属反光/布料褶皱）。AI 生成成功率高，和厨房物品主题契合度最高；且与现有 Graphics 占位（大色块+描边）视觉跳跃最小，替换后不会变成"另一个游戏"。
2. **像素风**：素材最多、包体最小、有怀旧加成；风险是物品拟物的可爱感打折。
3. **极简符号风**（《赵云与阿斗》路线）：成本最低但要求设计功底而非画功，是"设计出来的便宜"，不建议首选。

下一步动作：AI 按三种风格各生成一张"奶茶吸管塔"样张，看图拍板，选中风格固化成批量生成的 prompt 模板。

**参考对象**：

- 同品类教科书：《保卫萝卜》（国产 Q 版塔防巅峰，生活物品拟物当塔，与本项目同一条路）、《Bloons TD 6》（简单单位在满屏混战中的可读性）；
- 同平台验证：《羊了个羊》《肥鹅健身房》（简笔 Q 版在小游戏的吸量能力）；
- 素材实物：Kenney.nl（CC0 矢量简笔）、itch.io 搜 `cute tower defense` / `chibi sprites`、哩布哩布/Civitai 搜 `Q版游戏素材` / `chibi game asset`（选 LoRA 用）；
- 搜图关键词：`Q版塔防`、`Q版游戏素材 简笔`、`chibi game assets`、`kawaii game art`。
- 看图时的第一功能指标：**满屏多单位同时出现时能否一眼分清谁是谁**——比单张好不好看重要。

### 生产五步走

```
1. 资源清单   VISUAL_SKINS 注册表逐条列需求（已在代码里，天然存在）
2. 风格打样   同一物体×3种风格样张 → 拍板 → 固化 prompt 模板
3. 管线验证   1塔+1敌+1特效走通 sprite 分支（阶段1）
4. 批量生产   按清单生成 → 统一后处理（尺寸/透明底/描边）→ 填注册表
5. 包体优化   打图集 + 压缩 + 分包
```

### 成本估算

全套约 60~80 张图（4 塔×3 状态 + 5 敌人 + 子弹 + 10 特效 + UI）：AI API 费用几十元 + 图标约稿 100~300 元 + 素材库 0~100 元 ≈ **几百元以内，周期按天计**。

## 五、动画方案：程序动画优先

架构已是程序动画优先（见第一节），全游戏动画需求及解法：

| 动画需求 | 解法 | 需美术画什么 |
|---|---|---|
| 塔待机 | Tween 呼吸（scale 1.0↔1.05 循环） | 一张静态图 |
| 塔攻击（戳/旋/砸/射） | 沿用现有 executor transform 驱动 | 一张静态图 |
| 敌人行走 | Tween 组合：上下浮动 + 左右小摇摆 | 一张静态图 |
| 受击反馈 | 闪白 + 小幅击退位移 | 无 |
| 敌人死亡 | 缩小 + 淡出 + 旋转消散 | 无 |
| 爆炸/中毒/治疗等特效 | `ParticleSystem2D` 调参数（数量/速度/生命周期/颜色曲线） | 无（或一张小圆点图） |
| UI 反馈（卡牌弹出、按钮按压） | Tween bounce | 无 |
| **唯一例外：BOSS** | 简单帧动画（4~8 帧），用 Cocos 原生 `Animation` 播序列帧 | 一张 sprite sheet |

三个手段各管一摊：**Tween（主力，管位移/旋转/缩放/透明度）+ 粒子（特效）+ 音效（隐藏主角）**——动画真实感有一半是耳朵贡献的，戳击配"啵"、爆炸配闷响，同样动画打击感翻倍；音效有免费库（爱给网、freesound），零成本。

**行业常识：打击感的 80% 不是动画精度**，而是反馈时机——hit-stop、屏幕震动、受击闪白、伤害数字抛物线、音效音调，全是程序手段。

**与既有决策互证**：功能裁剪取消 Spine/DragonBones 模块压引擎体积，本方案一帧骨骼动画都不用，裁剪无副作用。Spine/龙骨在个人项目直接排除（包体大、小游戏端兼容坑、学习成本高）。

## 六、包体与平台适配（阶段 4 才做，先记录）

- 项目当前约 9MB（引擎占 6.5MB），微信主包 4MB 限制；
- 美术资源走分包（总量可到 20MB+）：战斗核心资源进主包并压缩，UI/特效分包按需加载；
- 批量生产时统一打图集 + 压缩。
