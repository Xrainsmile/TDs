# P2 四流派基线 · 试玩操作手册

16 局 = 4 流派 × 4 局，每流派 2 个固定种子（每种子 2 局）。

## 一、开局：不用拼 URL

Cocos 预览启动后**直接打开游戏即可，不需要任何 URL 参数**。所有配置走控制台命令。

### 第 1 步：生成命令（自动取 commit）

```bash
npm run playtest:launch
```

会打印类似：

```text
【第 1 步】浏览器控制台粘贴一次（持久化到 localStorage，刷新后仍有效）：

__TD_BASELINE__.setMeta({balanceVersion:'0.3.0', buildCommit:'4e7668b', playStrategy:'认真构筑', reviveEnabled:false, testGroup:'A'})

【第 2 步】每局开始前粘贴一行：

__TD_BASELINE__.run(1001, '奶茶供电流')   // 局1
...
```

commit 由脚本 `git rev-parse --short HEAD` 自动取，不用手工查。要改版本/策略：

```bash
node tools/playtest-launch.js --version 0.4.0 --group B --strategy 强追流派
```

### 第 2 步：控制台粘贴一次 setMeta

在浏览器控制台粘第 1 步那条 `setMeta(...)`。配置会存进 localStorage，**刷新页面后仍然有效**，所以整个 P2 只需粘一次。

### 第 3 步：每局粘一行 run

```js
__TD_BASELINE__.run(1001, '奶茶供电流')
```

会自动以该种子重开本局 —— **不用刷新页面，不用拼 URL**。第二个参数只是标注，会打印在导出报告的「目标流派」一栏，方便汇总。

辅助命令：`__TD_BASELINE__.info()` 看当前配置，`__TD_BASELINE__.clear()` 清除配置。

> 若因故要用 URL 方式（例如微信端），参数仍支持：`?balanceVersion=&testGroup=&playStrategy=&buildCommit=&seed=&revive=0`，中文需 URL 编码，微信端走 `wx.getLaunchOptionsSync().query`。

## 三、每局 SOP

### 开局自检（必做，5 秒）
开控制台确认参数已生效，缺任一行为参数没吃进去：

```text
[SeededRandom] 本局种子 1001，发牌与战斗随机可复现
[PlaytestMetadata] 复活已关闭（revive=0），失败面板不显示复活按钮
```

失败面板上**不应出现**「看广告复活」按钮。

### 局中：追什么
参数按 P2 规定填 `认真构筑`，但操作上必须主动追目标流派组件：

| 流派 | 追的组件 | 基础成立条件 |
| --- | --- | --- |
| 奶茶供电流 | 奶茶吸管 + 充电宝 + 核心供电改造 + 双管吸管改造 | 吸管 ∧ 充电宝 ∧ 核心供电 |
| 弹射毒爆流 | 杀虫喷雾 + 橡皮筋 + 毒爆改造 | 毒 ∧ 橡皮筋 ∧ 毒爆 |
| 控制爆破流 | 减速塔 + 牙刷 + 锅铲 | 三者齐备 |
| 串线剪断流 | 筷子 + 剪刀 + 彩色线轴改造 | 三者齐备 |

某局目标流派始终没成型时**不要中途弃局** —— 打完并导出，备注记「未成型」。这本身是「发牌能否支撑流派」的有效数据。

### 局末：立刻导出
结算弹窗点「导出记录」→ Web 下载 Markdown + JSON。或在控制台：

```js
__TD_PLAYTEST__.exportLatest()
```

**胜败都要导出**。每平台只存最近 20 局，16 局加试错局必超限，晚导会被挤掉。

## 四、人工补录（自动记录不到，每局补）

自动已覆盖：成型波次、伤害来源、漏怪、BOSS 时长与血线、最终金币、抽牌与决策耗时、机制触发计数。

导出的 Markdown 里预留了空位，每局补这三项：

- **每波主观压力**（1–5）：判断「建立压力 → 获得组合 → 释放压力 → 新威胁 → 再突破」是否成立。
- **三选一纠结度修正**（0–3）：自动值只按决策耗时估算，走神/阅读/误触要人工改。
- **爽点事件**：获取爽 / 成型爽 / 战斗爽 / 逆转爽 + 爽度 0–10。

口径见 `doc/playtest-record-template.md`。

## 六、陷阱

1. **换种子用 `__TD_BASELINE__.run(seed)`，不要点「再来一局」**。「再来一局」沿用当前种子（`playtestMetadata` 里的 seed 不变），不会换种子。只有 URL 方式才需要刷新页面换种子。
2. **晚导出会丢数据**。存储上限 20 局，超了挤掉最早的。
3. **别点复活**。即使 `revive=0` 已生效也看一眼按钮是否存在 —— 复活会回满血 +200 金币，直接毁掉该局金币数据。
4. **种子不等于逐帧复现**。只保证随机序列一致，操作顺序不同仍会分叉。对比同种子两局的差异即可看出操作影响。
5. **commit 必须真实**。`buildCommit` 非法会静默回退成 `unknown`，16 局就无法证明同版本。
